# Pool 背包系统功能说明 v1.3.1

2026-10-06。依据当前源码和 `SampleScene` 配置整理，已更新本日逻辑修复后的行为。数量、时长和捕获恢复规则仍是当前演示配置；修复验收见 [修复验证](inventory-fix-verification.md)。

## 1. 玩家操作

| 操作 | 行为 |
|---|---|
| WASD / Shift | 移动 / 奔跑，沿用玩家体力系统 |
| 鼠标位置 | 决定面朝与手电方向；怒冲锋开始后锁定方向 |
| E | 执行当前交互提示对应的拾取或拉闸 |
| 1–4 | 装备对应携带槽中的光球 |
| Space | 在对应区域使用当前装备球的融合能力 |
| 按住 Tab / 松开 Tab | 打开 / 收起只读快览，世界继续运行 |
| Esc | 打开暂停详情 / 返回游戏 |
| 暂停中点击物品格 | 查看说明，不改变实际装备 |
| 重新开始 | 重载当前场景，清空本局进度 |

## 2. 存放与拾取

| 类别 | 当前规则 |
|---|---|
| 情绪光球 | 固定四格，装备球也占一格。按拾取顺序排列；第一球自动装备，后续拾取不改变装备 |
| 任务物品 | 独立容量；按交互物列表中唯一有效任务 ID 的数量生成格数，按拾取顺序保存，每条记录数量为 1 |
| 电闸 | 只保存唯一 ID 的完成记录和完成数量，世界物体保留并变色，不占背包格 |

物品 ID 在三个类别之间也必须唯一。重复收集不会增加数量、发出数据变更事件或播放成功音。拾取后的光球与任务物世界对象隐藏；光球不会因使用能力而消耗。

同类不同 ID 的球分别占格，没有叠加能力。当前场景恰好有两个怒球、两个哀球；喜/惧球不在可拾取能力范围内。满光球栏拒绝第五球并保留世界对象，但不妨碍任务物收集。没有丢弃、替换、重排和堆叠操作。

拾取必须满足：对象已登记且处于启用状态、配置有效、容量足够、距离不超过 1.1 世界单位、到对象的射线没有被障碍阻断。暂停、结算、捕获、冲锋、眩晕和恢复操作所在帧拒绝拾取；直接调用 `TryCollect` 也遵循这套限制。

同范围内先选择可以交互的对象，再比较距离；同距离按任务物、电闸、光球优先级和 ID 排序。提示和 E 使用同一对象。失败显示约两秒提示；同类失败音间隔至少 0.5 秒。收集/换装格高亮 0.25 秒。

## 3. 装备与融合

装备按槽位记录。跨区保留装备；空格和重复装备不改变记录。冲锋/眩晕期间允许换装下一次能力，当前动作继续；暂停、捕获、结算期间拒绝换装。

| 装备与区域 | Space 的结果 | 当前参数 |
|---|---|---|
| 怒球 + 怒区 | 按释放瞬间面朝方向直线冲锋；撞到障碍后停止并眩晕 | 速度 16，冷却 4 秒，眩晕 0.65 秒 |
| 哀球 + 哀区 | 显示怪物和电闸的轮廓/方向标记 | 持续最多 8 秒，冷却 10 秒 |
| 不同情绪组合、过渡区、未装备 | 不启动能力，显示原因 | 不消耗球、不启动冷却 |
| 冲锋/眩晕中或对应冷却未结束 | 拒绝再次启动 | 不用换球取消动作或重置冷却 |

怒、哀按能力类型分别计时；两颗怒球共用怒冷却，两颗哀球共用哀冷却。换装和离区不清冷却。暂停冻结世界时间，因此冻结冷却和效果剩余时间。

哀透视离开哀区即结束，重新进入不恢复旧效果；换球不延长透视时间。已经开始的怒冲锋继续锁向直到撞障碍，跨区或换球不取消。当前没有冲锋超时或手动取消入口；应保证演示关卡有有效边界。

怪物行为属于现有区域系统，不由背包换装直接改写：怪物在哀区时可穿障，玩家也在哀区则奔向电闸；玩家离开哀区而怪物仍在区内时，以基础速度三倍追赶。怪物出区后恢复当地规则。离区提醒只解释规则，不透露隐藏怪物的实际位置。

## 4. 门条件与通关

当前场景配置四个任务物：镜片、铜片、纸页、记录纸；两个电闸：怒区电闸、哀区电闸。四个任务 ID 全收集且两个电闸 ID 全完成才开门。门打开后，玩家距离出口目标小于 0.6 世界单位即结算，冻结世界并显示重开按钮。

实际开门目标由 `requiredTaskIds` / `requiredSwitchIds` 决定。任务格容量和开门目标数量是两件事：加入物品并登记后会增加任务格，但不会自动加入开门条件。未列入 `requiredTaskIds` 的任务物只进入背包，不增加开门任务计数；详情明确显示“本关出口不要求该物品”，必需物显示“计入出口目标”。

两组目标必须都非空才视为已配置。任一组空缺时显示“开门条件尚未配置”，不自动开门。当前不支持只有任务物或只有电闸的关卡目标模型。

## 5. 暂停、捕获与重开

| 状态/操作 | 保存与恢复 |
|---|---|
| Tab 快览 | 不暂停、不减速；移动、瞄准、E、数字键和 Space 继续处理，格子不接收点击 |
| Esc 详情 | 世界暂停，玩法输入阻断，音频暂停；点击只查看；再次 Esc 或“继续”恢复原时间倍率 |
| 暂停当前冲锋 | 保留动作和锁向，恢复后继续；恢复所在帧不执行 E/Space/换装 |
| 被捕 | 按真实碰撞体接触判定，允许 0.02 世界单位接触容差；每个物理步检查相对运动，避免高速穿越漏判。约 1.25 秒后回入口，期间不能操作背包 |
| 捕获恢复 | 保留球、装备、任务物和电闸；玩家/怪物回各自初始位置，结束动作、透视和眩晕，清空怒/哀冷却；保护三秒 |
| 完整重开 | 重载场景，恢复世界物品，清空背包、装备、电闸记录、门进度和能力计时 |
| 失去窗口焦点 | 关闭快览，不主动暂停；Tab 必须释放后才能再次打开快览 |

捕获恢复并不是完整重开。当前恢复不主动补满玩家体力，不重置背包以外的关卡系统状态，也没有存档或退出游戏后续玩功能。普通怪物的预测捕获会被路径上更近的障碍阻挡；处于穿障状态的怪物可以越过障碍捕获。

## 6. 程序与关卡配置

玩家上的 `BackpackController` 提供交互物、视图、怪物、出口、门碰撞体、两组目标、范围和能力参数。每个 `BackpackInteractable` 配置类别、唯一稳定 ID、标题、描述、情绪和图标。

| 脚本 | 职责 |
|---|---|
| `BackpackData` | 携带数据、装备槽、分类完成记录、变更通知 |
| `BackpackController` | 输入、可拾取目标选择、距离/遮挡校验、提示和摘要 |
| `PlayerFusionController` | 分类型冷却、锁向冲锋、眩晕、区内透视 |
| `InventoryRunFlow` | 暂停、捕获恢复、门条件与结算 |
| `InventoryConfiguration` | ID、交互物引用、类别和目标一致性检查 |
| `BackpackView` / `BackpackPresentation` | 数据显示、查看选择、动态格子、标记与表现动画 |

配置校验已拒绝缺失交互物引用、同对象重复登记、空/重复 ID、目标不存在、目标类别错误和未定义情绪球。已配置两组门目标的场景还必须有出口、门碰撞体、玩家碰撞体、背包面板/文本/按钮/格子/滚动模板以及 EventSystem 输入模块；怪物存在时必须带碰撞体。交互半径和冲锋速度须为正，计时参数须为非负有限值，障碍层不能为空。普通 Unity 构建也执行校验。整张关卡的可达性仍需实际通关验证。

运行中不要修改已收集物品的 ID 或类别，也不要直接调用 `Data.Clear()` 作为本局重开：前者会让引用记录与 ID 索引分离，后者不会恢复世界对象的 `Completed` 和启用状态。使用 `Restart()` 执行正式重开。
