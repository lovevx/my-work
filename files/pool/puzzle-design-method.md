# 俯视角解谜设计思路拆解 v0.1

日期：2026-10-08  
参考作品：COCOON、Untitled Goose Game、Lara Croft GO、TUNIC、Monument Valley。

本文把公开资料确认的机制，与根据机制推导出的设计方法分开标注。以下方法是分析提炼，不代表开发者采用了完全相同的设计流程。Pool 部分沿用此前讨论的“恐惧决定目标、暴怒决定行动方式、环境决定结果”方向，属于新提案，尚未经过白盒或玩家验证。

## 1. 五款作品分别让玩家思考什么

| 作品 | 玩家主要思考的问题 | 可提炼的设计方法 |
| --- | --- | --- |
| COCOON | 物件应该放在哪里、带入哪个世界，才能组合它们的作用？ | 围绕已有操作，改变物件之间的关系和依赖 |
| Untitled Goose Game | 我做什么，会让这个角色作出对我有利的反应？ | 把可观察的动机和反应变成玩家能利用的规则 |
| Lara Croft GO | 调整某个物件，会同时改变哪些路径、威胁和机会？ | 让同一物件参与多条规则，通过位置与顺序出题 |
| TUNIC | 新线索能解释之前见过的哪些异常？ | 先留下疑问，再给予理解方法，让玩家回到旧场景验证 |
| Monument Valley | 怎样改变结构，让原本断开的路径连起来？ | 用清晰的空间关系承载发现与变化 |

它们强调不同的乐趣。角色行为解谜允许玩家设局，规则组合解谜强调安排关系，知识解谜强调重新理解，空间解谜强调看见结构变化。选择方法时，应先决定希望玩家在哪件事上获得成就感。

## 2. COCOON：围绕少量操作，改变关系

**资料确认的机制：** 世界存在于可搬运的球体中；球体还有可解锁的能力，能在其他世界中作为工具。玩家通过组合、移动与重排世界解谜。[官方机制介绍](https://www.cocoongame.com/)

**我的提炼：** 深度可以来自“同一件东西与谁发生关系”，而不是不断增加操作。球体作为容器和工具的双重身份，提供了组织谜题的空间。

可复用的出题流程：

1. 先安排一个简单情境，让玩家确认 A 的作用。
2. 引入一个位置或持有条件，让直接使用 A 无法完成目标。
3. 让玩家安排 B，改变使用 A 的条件。
4. 后续关卡重新组织 A、B 的依赖，让已有知识继续有用。

设计时要写出依赖关系：为了完成目标，哪个条件必须先成立？玩家能在哪里观察到这个条件？阻碍为什么让直接做法行不通？这比只写一串交互步骤更能说明谜题。

**用于 Pool 的例子：** 玩家先学会声音改变退避方向，再学会暴怒影响撞击能力。后续谜题要求玩家安排声源与怪物的相对位置，使退避目标和薄墙发生关系。不要直接告诉玩家“两个情绪组合可以开这面墙”；要让两条已知规则在场景里产生可推理的结果。

## 3. Untitled Goose Game：利用角色会作出的反应

**资料确认的机制：** 人物会追赶鹅以取回被偷的东西，也会整理场景；反应动作、视野、记忆和思考气泡帮助表达状态。开发者说明，互动结合了通用系统与手工制作的情境。[开发者访谈](https://www.gamedeveloper.com/design/behind-the-honk-an-i-untitled-goose-game-i-q-a)

**我的提炼：** 把角色当作有动机的参与者。谜题可以要求玩家改变角色的处境，再利用它的反应完成目标。

为一个行为谜题写四句话：

- 角色正在做什么？
- 什么事物会改变它的关注或目标？
- 玩家怎样预判、观察这个变化？
- 角色变化之后，给玩家创造了什么机会？

例如，一个原创情境可以是：守门者在意散落的工具，玩家把工具搬到门外，使其离开岗位去整理，再利用短暂空隙通过。这里的思考是如何制造机会；反馈要表达它为什么离开，以及何时可能返回。

**用于 Pool 的例子：** 声音对恐惧状态下的怪物应保持稳定意义：它退向远离声源的可达目标。玩家可通过移动声源间接安排怪物的位置。身体朝向、退避动作和运动轨迹应帮助玩家读懂反应，便于调整下一次布置。

## 4. Lara Croft GO：让一个物件同时改变多个问题

**资料确认的机制：** 敌人具有不同的运动模式；柱子可以填缺口、帮助抵达区域、击杀敌人，并阻挡滚石和箭矢。开发者明确提出增加机制之间的互动。[开发者复盘](https://mcvuk.com/development-news/the-develop-post-mortem-lara-croft-go/)

**我的提炼：** 给物件多种可理解的作用，再设计这些作用之间的取舍。玩家需要思考位置和先后顺序，因为改变一个状态会同时影响几条规则。

可复用的出题流程：

1. 为物件列出它对通路、视线、威胁或交互的作用。
2. 选出其中两种作用，使它们在当前布局中不能同时满足。
3. 提供重新布置或改变执行顺序的机会。
4. 让结果回到同一套规则下验证。

**用于 Pool 的例子：** 薄墙既封闭捷径，也隔断视线。撞开后，玩家获得新路线，怪物也能使用这条路线，玩家同时失去原有遮挡。谜题随后可以要求玩家决定回收时机与撤离路线。这样，破坏本身会影响下一步判断。

实时游戏还需要处理执行压力：给玩家观察位置和准备时间；把“预测错了”与“预测正确但移动太慢”作为不同的试玩问题记录。

## 5. TUNIC：用新知识重新解释旧场景

**资料确认的机制：** 收集的说明书页面提供地图、技巧与秘密。开发者的 GDC 演讲简介讨论用未解线索组织秘密，以及让秘密引出进一步的秘密。[官方机制介绍](https://store.steampowered.com/app/553420/TUNIC/)、[开发者演讲简介](https://gdcvault.com/play/1029384/-TUNIC-This-Was-Here)

**我的提炼：** 知识本身可以成为进度。玩家看过一个东西却没有理解它，后来获得证据或解释方法，再回到旧地点自主验证。

可复用的出题流程：

1. 提前放置能记住、能再次找到的异常。
2. 给玩家足够理由认为它有意义。
3. 在另一处提供理解它的证据或方法。
4. 允许玩家主动返回验证。
5. 在新的地方重复应用，证明学到的是规则。

**用于 Pool 的例子：** 玩家早期见到某种墙面的撞击痕迹；之后在安全位置观察暴怒怪物撞破同材质的墙。玩家可由此提出假设：之前那面墙也能被它撞开。此例成立的前提是材质、破坏能力和提示一致，不能只让指定任务墙有反应。

主线需要充分证据与验证机会。更隐晦的线索适合放在可选探索中，避免玩家因漏看一个细节而失去全部进展。

## 6. Monument Valley：把路径变化变成能看见的发现

**资料确认的机制与意图：** 游戏以不可能建筑、视错觉和隐藏路径为基础。ustwo 说明，其设计重视简单操作、新的发现与探索，而非不断提升挑战难度。[官方作品介绍](https://ustwogames.co.uk/our-games/monument-valley/)、[开发团队设计说明](https://ustwo.com/blog/monument-valley-out-now/)

**我的提炼：** 先让玩家看清目标与路径之间的关系，再让结构变化提供突破。操作带来的空间变化应能支持玩家判断下一步。

可复用的出题流程：

1. 让玩家看见目标，以及当前缺少的连接。
2. 明确表达可改变的结构。
3. 让变化持续、清楚地反馈到路径上。
4. 引导玩家重新观察通路，验证自己的判断。

**用于 Pool 的例子：** 玩家应在撞击前辨认薄墙的两侧，撞击后能看见洞口及后方区域。路径、遮挡与导航需要一致变化。俯视角下，前景墙不能遮住怪物的关键转向、撞击预备动作或新通路。

视错觉依赖特定镜头。Pool 可以借鉴目标和连接的表达；是否采用视错觉，应由游戏自身的空间规则决定。

## 7. 把五种方法组成 Pool 的一段教学与解谜流程

这是用于讨论与白盒验证的新提案。

### 第一步：观察并验证恐惧

给玩家一个安全的观察位置。怪物处于恐惧状态，玩家改变声源位置，观察其退避方向。让玩家有机会从两侧发声，确认退避与声源的相对关系。

要学到的规则：声音位置改变，远离声音的目标与路线也可能改变。

### 第二步：观察并验证暴怒

单独展示暴怒状态下的撞击能力，并清楚显示可破坏材质与撞击预备动作。让玩家把墙面特征与后果建立联系。

要学到的规则：暴怒改变行动能力；墙破坏后，通路与遮挡发生持续变化。

### 第三步：组合已知规则

设置薄墙另一侧的可达目标，并保留绕行路线。让玩家布置声源，使恐惧的退避目标落在合适方向；在暴怒状态允许破坏薄墙时，布局与通路成本应使撞墙路线成为合理选择。

链条：布置声源 → 退避目标改变 → 暴怒允许撞击 → 薄墙打开 → 双方路线改变 → 玩家重新选择回收与撤离时机。

这段设计需要单独核实目标选择和路径规则。不能由预设脚本把怪物直接送到固定薄墙，否则玩家移动声源也无法验证因果关系。

### 第四步：在新布局里迁移

交换声源、怪物与薄墙的相对位置，保持规则不变。观察玩家能否自主改变布置，而非重复上一关的位置与按键。

如果玩家能预判方向、解释结果，并利用新路线继续决策，才说明它开始形成可迁移的解谜理解。

## 8. 每道题的设计卡

| 字段 | 要写清楚的内容 |
| --- | --- |
| 目标 | 玩家能看到、能判断完成的结果 |
| 已知规则 | 玩家已经学过且能复述的规则 |
| 证据 | 当前场景里支持猜想的线索 |
| 阻碍 | 直接做法为何不能完成目标 |
| 核心推理 | 玩家需要想到的关键关系 |
| 可做的实验 | 怎样低成本验证一个猜想 |
| 失败反馈 | 失败后，玩家获得什么信息 |
| 成功后的状态 | 通路、威胁或资源发生什么变化 |
| 迁移问题 | 换一套布局，规则还能怎样使用 |

试玩记录要区分四种情况：没有注意到线索、理解了线索但规则预测错误、预测正确但操作失败、偶然成功却无法解释。只记录是否通关，无法判断题目是否实现了预期的思考过程。

建议先验证“行为可读 + 规则可组合 + 结果会影响下一步”这一小段循环。线索回收和空间表达服务于它；先让未读文档的玩家说清因果关系，再决定扩展多少谜题。
