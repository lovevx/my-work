# Pool 背包逻辑修复与验证

2026-10-06。针对 [修复前检查报告](inventory-review.md) 的四项优先问题实施修复；基线提交 `8c2745a`。背包布局仍为 v1.3.1，未增加新的物品能力或经济规则。

## 修复结果

| 问题 | 修改后的行为 | 验证 |
|---|---|---|
| 下方接触不触发捕获 | 用真实碰撞体间距检测接触，容差 0.02；在物理步扫掠双方相对运动，防止高速经过漏判。普通怪物的扫掠被更近墙体阻挡，穿障怪物可跨墙捕获 | 四向接近、三秒保护、保护结束、暂停、高速怪物、高速玩家和墙体阻挡 |
| 删除出口仍可构建 | 有有效门目标时必须有出口、门碰撞体、玩家/怪物碰撞体以及背包必需 UI 引用和输入系统；校验交互范围、速度、计时与障碍层 | 普通构建校验拒绝空出口/门/视图/详情文本/模板及无效数值，原场景通过 |
| 区域读取物理/显示位置不一致 | 玩家移速、怪物目标、区域穿障、三倍引出速度及追击方向统一从刚体位置计算；无刚体的目标仍使用 Transform | 插值开启时传送跨区立即选玩家并得到三倍速度；双方回哀区选电闸；怪物出区恢复碰撞 |
| 可选物文案错误 | 必需任务物显示“计入出口目标”，可选物显示“本关出口不要求该物品”；两种详情路径共用用途规则，目标成员变化后刷新 | 可选物增加携带量但不增加门进度；查看文案正确，改成必需物后刷新 |

配置缓存现在包含出口、门、视图、怪物和数值参数的变化；移除/恢复出口会立即改变有效配置状态。没有两组门目标的未配置场景仍不自动开门，也没有强制加入怪物。

完整回归的传送使用刚体位置并等待固定步；失败记录包含玩家/怪物物理与显示位置、区域和速度。捕获回归恢复真实物理模拟，不再依赖禁用模拟后强行覆盖显示位置。

表现回归的快览动画终点改为读取场景实际编辑位置，并记录预期/实际位置，避免把旧默认坐标当作唯一合法布局。本次核对的场景仍使用默认位置；没有修改当前布局来迎合测试。
