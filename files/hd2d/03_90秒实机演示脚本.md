# 实机演示与录屏脚本

用途：执行策划与系统策划面试展示。已备齐真实游戏截图；本文件是待录制的实机演示脚本，并非已经录好的视频。

## 90 秒展示顺序

| 时间 | 画面与操作 | 讲解重点 |
|---|---|---|
| 0–8 秒 | 港口全景，再切森林探索 | 个人全程负责，AI 辅助；展示动作 RPG 的系统落地。 |
| 8–25 秒 | 战斗中展示三段斩击，再展示一次闪避或命中后接技能 | 三段连招、输入缓冲、命中取消与第三段恢复的取舍。 |
| 25–40 秒 | 森林中央路线与西侧坡道；镜头扫到补给目标 | 固定空间遭遇、可选路线；地图通路与碰撞同步。 |
| 40–57 秒 | 回收补给后展示撤离与追猎选项；切到巨虎战 | 基础收益先确认，追猎携带剩余资源，击杀奖励独立结算。 |
| 57–75 秒 | 回港前战利品整理，再开角色与成长预览 | 装备、材料和永久成长形成循环，数值变化在操作前可见。 |
| 75–90 秒 | 展示验证摘要，结束在港口画面 | 规则已落地；说明工程检查与玩家体验验证的区别。 |

## 连贯配音稿

这是我全程负责、使用 AI 辅助制作的 HD-2D 动作 RPG 原型，重点是把设计规则做成可玩的系统。战斗采用三段连招，前两段命中后可以衔接技能，第三段保留恢复，让输出与防守有取舍。森林采用固定空间遭遇，提供中央路线和西侧坡道。完成基础履约后，玩家可以撤离，也可以带着剩余资源挑战巨虎，争取额外成长奖励。回港前能整理战利品，之后进行装备与属性成长。我会把流程拆成状态、条件、奖励和异常分支，再通过原型与工程检查核对。当前已有验证记录，下一步重点是陌生玩家对路线、收益和战斗节奏的理解测试。

## 录制准备

1. 在 Godot 打开 project.godot，F5 运行；使用主菜单“森林试玩 / 继续试玩”，该入口使用独立森林档。若需重录，先确认只重置试玩档；不要用“开始新游戏”覆盖普通档。
2. 检查默认操作：WASD 移动、左键斩击、Space 闪避、V 交互、C 角色、J 任务、F1 帮助、Esc 菜单；改过键时以游戏提示为准。
3. 录制 1920×1080 或 1280×720 横屏画面；用录屏软件的游戏捕获（Game Capture），保持鼠标可见。视频按任务段落剪辑，保留能看出操作与反馈的连续镜头。
4. 为港口、森林、巨虎、清理和成长分别录短段落，按上表组装。90 秒并不要求连续通关；可以剪掉赶路与加载，保留真实操作。
5. 若用关卡调试或准备好的测试状态，画面标注“调试状态演示”；不要将自动击杀、修改存档或调用内部函数的镜头当作自然通关。

## 面试现场三分钟版

第一分钟介绍项目范围与个人职责；第二分钟用“履约后是否追猎”说明触发条件、资源消耗和收益；第三分钟展示一次成长预览，并讲一个通路或重复领奖的修正案例。不要从技能清单逐项念起。
